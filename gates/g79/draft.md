# G79 · Does an identified Kalman filter improve transient power estimates? (RQ2)

Draft for owner review. Solver selection, dry-run results and a numerical bar are pending. The task is due before the 15 January 2027 protocol freeze (`fyp/todo-gates.md:72`, `fyp/goals.md` §§6 and 20, `fyp/tasks.json` `g79-kalman`, `fyp/protocol.md`).

## Why this gate

G44 generated 3D-ICE sensor and region traces at **0.5 ms** and used a per-sample Bayesian steady inverse alongside a dynamic model. Its reduced plant came from ERA on step responses, with a modal fit as a fallback. `plant62.py` extends that construction with per-die mean input directions. G62 loads `Ae`, `Be`, `Ce`, the power basis `D` and sensor indices from `plant62.npz`. G68 generated its observations with that same discrete plant and estimated the unknown power coefficients with an augmented Kalman filter and a mean-reverting input process. Its quasi-static arm applied the steady Bayesian inverse to each reading. The plant was identified in origin and matched by construction in G68's test. G68 reported projected and unprojected power errors. Sources: `experiments/scratch_archive_2026-10-29/sens/{g44,plant62,g62,g68}.py`.

G81c's validity run reproduced the G69 guard-margin chain after `plant62.npz` was restored byte-identically from `experiments/scratch_archive_2026-10-29/sens/`. This establishes replay of that exploratory chain. G44 and G68 remain feasibility work until re-run in the clean FYP testbed. Use their design as a starting point and build new traces and a new fit for this gate. Sources: `gates/g81c/README.md` and `registration.md`, `fyp/failures.md` G81c entry, `fyp/plan.md` §2.3.

## One gated comparison

On the G93a `3d` stack, compare a causal **identified-plant augmented Kalman filter** against a **G44-style quasi-static Bayesian power estimator**. Both infer buried-die power each slot from the same sparse temperature readings and the same activity pseudo-measurement. The quasi-static estimator conditions the train-fitted power prior on the current slot using a train-derived steady sensor response. The Kalman arm uses a stable reduced dynamic model and carries the estimated thermal and power state between slots. Both use the same train-derived power basis, initialization information, sensor geometry, and score mask. Calibrate any method-specific hyperparameters on the same calibration groups. Score the unprojected truth in the common power bins so that basis truncation cannot erase an absolute error.

For each trajectory and paired sensor-noise draw, use the RMS error of the buried-die bin powers across the scored slots and bins (W per bin). Form the paired improvement as quasi-static RMSE minus Kalman RMSE. Average paired differences within each program, then average the program means with equal weight. Report the individual program differences and the group-level uncertainty. Fix the minimum improvement and decision rule only after the dry run. A valid miss means the identified filter has not demonstrated the required gain on this stack, cadence, sensor model and held-out programs.

**Reported controls.** Report the matched exact-plant versus identified-plant gap using the same readings, prior, basis, noise and scoring. Use the known thermal step operator in the exact arm and the train-trace fit in the identified arm. Plan the matched pair on PACT even if the owner chooses 3D-ICE or HotSpot for gated truth. Fit the identified control from its own PACT train traces and compare both control arms on the same held-out PACT traces. Size this reported control during the dry run. If full-size filtering is too expensive, use a separately pinned smaller PACT mesh with the same train/test separation and report the gap for that mesh. The known operator is exact for the discrete thermal dynamics on the shared input basis. Quantify any operator reduction separately. Defer Gillijns–De Moor and constrained moving-horizon estimation to a later gate, where unknown-input rank and horizon/constraint choices can be checked before comparing them.

## Time conventions · check before registration

- Use 0.5 ms as the initial sample-period candidate (archived `g44.py::DT`). Subdivide each filter interval into equal, representable solver rows. The 0.125 ms substep in the cost estimate is a pilot setting. Confirm the chosen step and a finer step on the actual converter and pinned solver, including 3D-ICE's parser and row-count guards (`opentsense/stack/to_3dice.py::steps_per_slot`, `gates/g94/solve.py`).
- With `k` zero-based and slot length `Δ`, input `P[k]` acts on `[kΔ,(k+1)Δ)`. The state at `kΔ` advances using that input. Observation `y[k]` is the reading at `(k+1)Δ`, tagged to the power of the interval just completed. With `m` solver rows per slot, that sample ends at zero-based row `m(k+1)−1`. Row 0 is the end of the first row. Thermal and sensor initial states at `t=0` are separate. Publish explicit time and source-window indices, and score a slot only with information available by its observation time. Match `gates/g94/solve.py::on_grid`.
- Stock PACT's Xyce PWL has a one-slot input delay. The PACT path under consideration is `run.pact_transient`, whose backward Euler uses row `k` without that delay. HotSpot must use the patched G94 build and the converter's `init_temp = stack.ambient_K`. HotSpot advances once per trace row, so refine by subdividing the trace (`gates/g94/draft.md` solver survey, `opentsense/stack/to_hotspot.py`, `opentsense/thermal/run.py`).
- Exercise a zero segment, a tagged pulse and its falling edge, and a known asymmetric sensor location. Compare the first and offset samples with an analytic small case and check expected row count, sample times, coordinate orientation and power integrals. Check that incorrect initial-temperature, one-row-shift and beginning-of-slot interpretations fail the pulse comparison. Fix any alignment error before scoring or freezing the protocol.
